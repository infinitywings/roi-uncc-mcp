# M29-R executor backbrief

## Mission interpretation

M29-R is an offline construct-validity repair after M29-A qualified the
implementation boundary but did not show hybrid complementarity. The central
question is no longer whether an LLM can call an optimizer. It is whether a
typed composition of semantic strategy compilation and deterministic numerical
search can solve registered multi-stage decisions that neither component solves
alone under a matched evidence and authority boundary.

The study remains `PRELIMINARY_ONLY`. It may support a proposal for a later
bounded simulator gate, but it cannot support claims about physical impact,
stealth, detector evasion, defense bypass, generalization, or confirmatory
performance.

## Causal factorization

Every case begins as a latent formal specification. That specification defines
the oracle `StrategyProgram`, the numerical response surface, and the oracle
multi-window plan before any natural-language rendering. A deterministic
renderer then produces an `EvidenceBundle` containing:

- operational bulletins and doctrine excerpts;
- source authority, validity intervals, and supersession lineage;
- topology relations and strategy-dependent target scope;
- a per-window numerical candidate surface; and
- machine-readable hard type, range, and resource limits.

All evaluated arms receive the same authoritative bundle bytes for a case. The
registered factors change only the machinery available to interpret or act on
those bytes.

## Arm ladder

| Arm | Semantic compiler | Numerical planner | Retrieval | Role |
|---|---|---|---|---|
| `IA3-O` | None; registered neutral program | Exact deterministic optimizer | None | Optimizer-only control |
| `IA3-SO` | Frozen symbolic compiler | Exact deterministic optimizer | None | Rule-engine control |
| `IA4-D` | LLM typed compiler | LLM direct plan | None | Direct-LLM control |
| `IA4-H` | LLM typed compiler | Exact deterministic optimizer | None | Core hybrid |
| `IA4-HR` | LLM typed compiler | Exact deterministic optimizer | Existing embedding service | Retrieval hybrid |
| `IA5-OC` | Latent oracle compiler | Independent exact oracle | None | Attainable ceiling, not an attacker arm |

`IA3-O`, `IA3-SO`, `IA4-H`, and `IA4-HR` must use byte-identical optimizer
code and candidate surfaces. `IA5-OC` uses an independently implemented oracle
enumerator so that the tested optimizer does not define its own ground truth.

## Registered estimands

1. `IA4-H - IA3-O`: value of semantic compilation when both receive the same
   evidence bytes and use the same numerical surface.
2. `IA4-H - IA4-D`: value of deterministic numerical search after semantic
   interpretation.
3. `IA4-H - IA3-SO`: value of LLM compositional interpretation beyond a
   frozen rule engine.
4. `IA4-HR - IA4-H`: value of scoped retrieval on retrieval-required cases.
5. `IA5-OC - IA4-H`: remaining compiler-plus-planner headroom.

The primary M29-B unlock endpoint is conjunctive. A hybrid cell succeeds only
when its compiled program is semantically correct, its plan is valid, and its
plan matches the independently enumerated oracle or falls within a frozen
regret tolerance. Aggregate plan accuracy cannot conceal compiler failure.

## Counterfactual battery

The planned development battery has eight mirrored intervention pairs and 16
conditions. Each condition has four decision windows and a non-trivial
candidate surface. The registered intervention classes are:

1. doctrine objective-priority reversal;
2. topology relation reversal;
3. authority and supersession reversal;
4. validity-expiry shift;
5. resource-budget disclosure;
6. delayed evidence arrival;
7. gradual bias horizon or cooldown change; and
8. retrieval distractor plus lineage correction.

At least half of the conditions must require selecting and scheduling more than
one non-noop action. At least four conditions must implement gradual bias
accumulation across three or more windows. These are synthetic planning
constructs; `visibility_cost` is an accounting feature, not a detector or
stealth measurement.

## Retrieval boundary

The authoritative strategy corpus is frozen locally before any embedding call.
`IA4-H` receives a token-budgeted flat rendering from that corpus. `IA4-HR`
receives top-k passages selected from the same corpus using only the already-
running RKA-configured embedding backend. The expected service identity is:

- owner: `existing_project_RKA_service`;
- RKA endpoint: `http://127.0.0.1:9712`;
- backend: `openai_compat`;
- model: `qwen3-embedding:0.6b`;
- dimensions: `1024`.

The service may be probed and called only after the design, corpus, query set,
top-k rule, and plan-validation gate are frozen. No model may be started,
restarted, replaced, or reconfigured. Retrieved passage IDs, scores, service
identity, latency, and call/item counts must be retained. Retrieval may never
query RKA journal, decision, mission, claim, or governance content.

## Error-focused design

M29-A errors motivate, but do not label, the new cases. M29-R explicitly tests
budget changes, sensitivity-direction changes, validity holes, operating-point
changes, delayed feedback, and contradictions inside multi-window programs.
The cases are generated from new latent specifications and new development
seeds; M29-A answers are not copied into the M29-R oracle.

## Fail-closed boundaries

- No Docker, simulator, HELICS, OpenDER, GridLAB-D, detector, defense, network
  impairment, physical actuator, final record, or seed `9101` through `9112`.
- No attacker-facing access to RKA governance data.
- No prompt tuning on registered conditions.
- No LLM output directly selects an actuator command. It must parse as a typed
  `StrategyProgram` or `AttackPlan` and pass the common validator.
- Provider, parser, embedding, retrieval, optimizer, validator, lineage, and
  token-limit failures are distinct terminal outcomes.
- Every attempt is create-once and content-addressed. No overwrite or silent
  retry is permitted.
- M29-B remains locked until a separate evidence-review gate returns `GO`.
